+# V0.2 — Normalisation locale de métadonnées HTTP non vérifiées
+
+**Statut : composant Python hors ligne, non connecté à un collecteur, non déployé.** Ce module est une préparation additive des work packages `P2S-WF-E03`, `P2S-WF-E05` et `P2S-WF-Q01`, et ne satisfait pas leurs critères d'acceptation de bout en bout.
+
+## Contrat
+
+```python
+from app.http_metadata_normalizer import normalize_untrusted_http_metadata
+from app.public_summary import build_guest_public_summary
+
+evidence = normalize_untrusted_http_metadata(200, [
+    ("Content-Type", "text/html"),
+    ("Strict-Transport-Security", "max-age=31536000"),
+    ("Set-Cookie", "sensitive=never-export"),
+])
+summary = build_guest_public_summary("https://example.com/", evidence)
+assert summary["status"] == "UNVERIFIED_SUPPLIED_EVIDENCE"
+assert summary["audit_performed"] is False
+assert summary["site_contacted"] is False
+```
+
+- Entrée : code HTTP déclaré (entier strict 100–599) et jusqu'à 64 couples `(nom, valeur)` de headers fournis par l'appelant.
+- Noms de headers ASCII token valides, longueur ≤128 ; valeurs UTF-8 valides, ≤2 048 octets chacune, sans contrôles ASCII, budget cumulé ≤16 384 octets.
+- Sortie : uniquement les noms normalisés et triés d'une liste publique fermée : Content-Type, HSTS, CSP, X-Content-Type-Options, Referrer-Policy et Permissions-Policy. **Aucune valeur, aucun cookie, aucun jeton, aucune URL de redirection, aucun serveur ou identifiant n'est restitué.**
+- La sortie utilise exactement `UNVERIFIED_SUPPLIED_PUBLIC_RESPONSE` et reste compatible avec le moteur `app.public_summary`. Une absence d'en-tête dans un échantillon incomplet ne prouve pas son absence sur le site.
+- Une valeur invalide échoue de manière conservatrice avec un message générique, sans recopier les données sensibles.
+
+## Limites de confiance
+
+Le module ne fait aucun DNS, HTTP, crawling, stockage, découverte PHP, analyse de CVE ou correction. Il ne prouve pas que les données proviennent d'une cible, que le propriétaire a donné mandat ou qu'un site est sûr. **Ne pas le présenter comme un collecteur ou un audit réel.**
+
+La future collecte P1 exige préalablement les mandats, l'authentification, le contrôle du pair IP réel à chaque connexion et redirection, le DNS rebinding, les règles robots, quotas, annulation, isolation réseau et preuves signées/revocation. La future sauvegarde de rapports exige un compte réel, une ACL par projet et une politique de rétention. PHPPATCH reste séparé et soumis à approbation.
+
+## Vérification
+
+```bash
+python -m unittest discover -s tests -v
+```
+
+La CI historique exécute les tests du nouveau module, notamment non-divulgation de valeurs, doublons, contrôle des tailles, Unicode malformé et raccordement au résumé anonyme sans promotion de confiance.
+
+Le programme V0.1→V1.0, six lots, 32 exigences, 61 work packages, moteur commun, Docker isolé et les deux destinations S1 demeurent inchangés. Aucune opération S1 ni modification de `main`.
