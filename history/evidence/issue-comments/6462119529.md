## ADDENDUM PRODUIT — P2S-UX-002 — parcours visiteur → compte → propriétaire vérifié (28/10/2026)

**Continuity ID :** `PHP2SHELL-CONT-20261027-ROOT-01`  
**Ancre antérieure :** [checkpoint #030](https://github.com/chainsolutions-wealthtech/Php2shell/issues/5#issuecomment-6462062970).

**Nature :** décision produit/spécification additionnelle, **NON code implémenté**, ne remplace aucune capacité ou autorisation existante ; aucune nouvelle branche/PR, aucune mutation S1.

### Trois états progressifs, inclusifs et distincts

**A. Visiteur anonyme, aucune inscription ni liaison GitHub imposée.**
- Coller une URL puis cliquer **Analyser** → produire une réponse **courte et utile** fondée uniquement sur des informations publiques effectivement disponibles et une éventuelle vérification de surface **légère, admise, sécurisée**. Ne jamais feindre d'avoir scanné un site si seul un préflight local a été effectué.
- Montrer un aperçu des constats réellement établis, leur degré de confiance, les limites, et une action **Créer un compte pour obtenir et conserver un rapport détaillé**.
- Pas d'historique personnel ni de stockage d'un rapport privé complet anonyme ; appliquer limites anti-abus, quotas, protections SSRF pour toute requête HTTP autorisée, sans exploration intrusive ou code privé. Politique de conservation minimale des traces techniques nécessaire à la sécurité, distincte de l'historique personnel.

**B. Utilisateur inscrit, site non nécessairement possédé.**
- Connexion simple et unique à PHP2SHELL/PHPPATCH (fournisseur OIDC / lien email sécurisé à choisir et vérifier), **GitHub facultatif**.
- Générer ou compléter un **rapport détaillé sur les données publiques autorisées** : preuves et incertitudes, constats, technologies détectées vs supposées, limites, conseils, dates et historique.
- **Sauvegarder le rapport dans l'espace privé de l'utilisateur**, retrouver/reconsulter les analyses, lancer une nouvelle version autorisée, gérer la conservation et suppression. Sauvegarde après compte et consentement ; ne pas afficher un rapport détaillé fictif préexistant si seule la courte synthèse a été calculée.
- L'inscription seule ne donne aucun droit d'analyse privée, de crawl agressif, de patch ni de déploiement sur un site tiers.

**C. Propriétaire / administrateur réellement vérifié.**
- L'utilisateur revendique un site ; le backend vérifie réellement sa maîtrise ou un mandat valide (preuve DNS TXT, fichier de validation contrôlé, méthode d'administration approuvée ou délégation vérifiable, avec expiration/révocation). Une case à cocher ou un domaine saisi ne vaut pas preuve.
- Option **Connecter GitHub** (OAuth/GitHub App préexistante, scopes minimaux) puis **choisir explicitement le dépôt autorisé** ; contrôle des droits réels `read`, identité du repo, exact HEAD et traçabilité, sans demander le token à la main.
- **La permission GitHub sur un dépôt ne prouve pas automatiquement la propriété d'un domaine** ; relier le domaine et le dépôt par une preuve ou délégation distincte et enregistrée.
- Après admission P2 ciblée, enrichir l'audit : code PHP privé autorisé, `composer.json`/`composer.lock`, configuration et runtime attestés, niveau de confiance, conseils de correction ; PHPPATCH propose des diffs, tandis que tests, revue indépendante, patch appliqué et déploiement nécessitent **des autorisations distinctes**.
- Le propriétaire ne devrait voir **que les étapes nécessaires** : prouver le domaine, connecter éventuellement son repo, confirmer l'analyse. Les mandats, signatures, ACL, P1/P2, MCP et locks restent gérés en arrière-plan.

### Exigences d'architecture et d'expérience utilisateur

- **Progressive disclosure** : une zone URL, CTA Analyser, résumé public visible, puis inscription pour détail enregistré, puis option « C'est mon site » pour accès approfondi ; **pas de barrière d'inscription avant la réponse courte**.
- **Une seule identité utilisateur** pour les deux consoles, mais droits par projet/actif et opération ; modèle distinct `GUEST_PUBLIC_SUMMARY`, `ACCOUNT_DETAILED_PUBLIC`, `VERIFIED_OWNER_P2` (noms de produit, **pas** autorisations runtime).
- Persistance : `user`, `site`, `verification`, `github_connection` (secrets protégés), `repository_mapping`, `analysis`, `report_version`, `consent`, `audit_event`, avec contrôles d'accès, chiffrement/protection et durées de conservation à concevoir. Ne pas confondre entrée GitHub et compte du produit.
- Idempotence, coordination des agents, jobs/reprises/quotas, preuve exacte des opérations et suppression des données privées suivant politique. Aucune nouvelle autorité MCP parallèle.
- Expliquer honnêtement les analyses publiques possibles sur tout site vs opérations nécessitant l'autorisation de son propriétaire. Pas d'exploit, bruteforce, inspection code privé ou scan intrusif sans mandat.

### Tranches futures indépendantes — à intégrer au plan existant sans reclassification abusive

1. **UX / Tests** : page visiteur URL → petit résultat issu uniquement de preuves publiques autorisées ; CTA inscription, sans faux statut « analysed ».
2. **Session / stockage** : authentification utilisateur réelle, compte et rapport persistant, contrôle d'accès et suppression ; ne pas supposer que le MCP agent OAuth est un IdP public.
3. **Propriété vérifiée** : challenge domaine/mandat, preuves, invalidation/expiry/révocation et gestion de sites.
4. **GitHub facultatif** : autorisation déléguée lecture seule du repo, mapping domaine↔repo soumis à vérification, analyse source P2 admise.
5. **Rapport et PHPPATCH** : diagnostic progressif, propositions puis validations et déploiement uniquement gouvernés.

**Critères d'acceptation fonctionnelle** : (i) visiteur reçoit une vraie réponse courte sûre sans inscription ; (ii) après connexion, obtient un rapport détaillé autorisé enregistré dans SON compte ; (iii) connexion GitHub entièrement facultative sauf pour l'option d'analyse du dépôt ; (iv) seul le propriétaire/mandataire vérifié peut consulter le code privé ; (v) les analyses et corrections restent interdites tant que leurs prérequis ne sont pas remplis ; (vi) chaque statut repose sur une preuve observable, jamais une promesse UI.
