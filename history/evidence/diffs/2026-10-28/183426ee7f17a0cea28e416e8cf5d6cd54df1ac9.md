+# V0.2 — Dossier d'audit local et plan de remédiation à valider
+
+**Statut : prototype hors ligne implémenté en PR #2.** Ce document est une étape vers le parcours cible URL → crawl autorisé → diagnostic → rapport → PHPPATCH, **pas** le fonctionnement réseau ou Web complet.
+
+## Objectif
+
+Assembler en un même dossier les signaux issus des fichiers PHP, des réglages PHP ini/FPM et, si fourni, d'un **runtime déclaré non attesté**. Ce dossier peut servir de **contrat de données futur** pour le frontend PHP2SHELL, les rapports et l'espace PHPPATCH, mais ne valide aucune vulnérabilité et ne génère ni n'applique de patch.
+
+## Exécution locale
+
+```bash
+python -m app.cli audit-dossier \
+  --path ./projet-php-autorise \
+  --as-of 2026-10-28 \
+  --format json
+
+python -m app.cli audit-dossier \
+  --path ./projet-php-autorise \
+  --as-of 2026-10-28 \
+  --runtime-file ./runtime-declare.json \
+  --format markdown
+```
+
+Le format par défaut est **JSON** ; `markdown` produit un brouillon de rapport en sortie standard. Aucun fichier n'est écrit, aucun appel réseau ni PHP n'est exécuté par cette commande.
+
+## Champs et décisions
+
+- `document_type=PHP2SHELL_LOCAL_AUDIT_DOSSIER_DRAFT`, `vulnerability_verdict=INSUFFICIENT_EVIDENCE`, `production_safe_to_patch=false`.
+- `observations[]` : identifiant de preuve stable, règle, sévérité **indicative**, chemin **relatif**, ligne, `confidence=review_required`, proposition de remédiation prudente, `patch_status=NOT_GENERATED`.
+- `declared_runtime` si le fichier JSON optionnel existe : version/SAPI **déclarées**, âge, comparaison aux seuils CVE, toujours **`signature_verified=false`, `mandate_authorization_verified=false`, `effective_http_runtime_attested=false`, `asset_applicability=insufficient_evidence`**.
+- `report_fingerprint_sha256` : empreinte stable des résultats normalisés, **pas** une signature cryptographique ni un identifiant d'actif ou d'approbation.
+- `next_gates[]` : mandat authentifié, revue humaine, preuve PHP/SAPI/backports, rapprochement CVE, tests isolés, approbation et rollback.
+
+Les chemins absolus du projet, valeurs de configuration brutes, code PHP brut, contenu de `composer.json`/`composer.lock`, URLs privées de dépôt, clés et références de mandats ne sont **pas exportés**. Les chemins relatifs et propositions textuelles sont neutralisés avant insertion dans Markdown. Les rapports comportant plus de 2 000 observations sont refusés ; il faut alors répartir la campagne.
+
+Un résultat **sans constat** n'est pas un certificat de sécurité : la détection actuelle est lexicale et non AST/dataflow.
+
+## Non-régression et limites de la mise en production
+
+- `check-version`, `scan-local`, `review-runtime-evidence`, les exports CSV/JSON existants, la collecte GHSA bornée et les approbations antérieures restent conservés.
+- Aucun pipeline d'audit URL/crawl réel, aucune authentification frontend, aucun rapport PDF ni signature de preuve, aucun Docker worker/API FastAPI, aucun patch PHPPATCH ni déploiement sur S1 ne sont créés par cette étape.
+- Les recommandations **ne sont ni des patchs, ni des ordres de changement**. L'interface PHPPATCH devra créer de véritables diffs, tests et preuves d'approbation dans une tranche ultérieure, sur des dépôts locaux explicitement autorisés.
+- Les tests `tests/test_audit_dossier.py` vérifient secrets non exposés, matrice de confiance non élevable, sortie Markdown, CLI, absence de réseau, absence de résultat ≠ sécurité, et stabilité de l'empreinte. Vérifier les CI au **SHA exact**.
+
+**Suite :** ajouter une API de lecture authentifiée, les campagnes autorisées et le moteur de rapports complet, puis les interfaces distinctes `php2shell.wealthtechinnovations.com` et `phppatch.wealthtechinnovations.com` sur un moteur commun et Docker isolé. Le déploiement reste gouverné par MCP après capacité/mandat effectifs, avec tests et rollback.
